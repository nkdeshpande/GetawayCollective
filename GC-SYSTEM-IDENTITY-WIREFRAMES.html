GC-900 through GC-930 / public system projection

Quiet, explicit system moments.

Identity and system routes are not marketing pages and they are not Office utilities. They use the same GC geometry and calm, but remove all visual ambiguity: what happens next, what is safe to enter, what is pending and what cannot be seen are stated plainly.

GC-900 / System · IdentityPublic / canonical route: /sign-in → internal /auth/sign-in

Identify me.

The sign-in screen is an intentional threshold, not a generic account page. It contains one method, one safe promise and one recoverable exit. No personalisation appears before a valid session exists.

Primary jobCollect an email address to initiate a secure session verification.
Primary controlEmail field + “continue” action. No commitment, document or personal record is shown here.
Success exitCreate a pending identity/session context, then route to GC-910 Verify. Verification token is never placed in the URL path.
Desktop wireframe

A single considered threshold.

Void ground signals a private boundary. The form is deliberately narrow and centred. A return link is always present; no external identity provider is implied until a provider is actually selected.

01GC mark and “Sign in” establish context without navigation clutter.
02Email is the only requested field; explanation comes before capture.
03Privacy and delivery limitations sit under the action, not hidden in legal copy.
04On success, the action becomes “Code sent”; do not silently redirect.

GC-910 / System · IdentityIdentified access / canonical route: /verify → internal /auth/verify

Prove the address.

Verification is only reachable after an identity request has been initiated. The one-time code is delivered out of band and checked in the request/session context—never in a path segment, never in a screenshot-friendly URL.

Entry conditionPending identity created by GC-900. Direct/expired entry returns to Sign In without revealing any account state.
Primary controlSix-digit code, paste support, resend timer and a change-address exit.
Success exitCreate verified session, restore the requested safe destination or present the appropriate default aperture.
Desktop wireframe

Verify once, then return with context.

The screen carries the minimum identity context: masked destination, expiry/resend timing, and a route back to change the address. It never tells someone whether the address has an Investor, Member or Office relationship.

01Mask address consistently: `ni•••@domain.com`; show “change” rather than an editable address here.
02Use six individual visual cells with one logical accessible code input behaviour.
03Auto-advance is optional; paste must distribute digits and preserve keyboard backspace.
04Resend becomes available at a defined time; retry counts/rate limits are not disclosed.

GC-920 / System · StatusPublic route: /status · aggregate health only

Is the platform healthy?

Status is a public trust surface. It reports only aggregate platform conditions and incident communications. It never reveals infrastructure topology, sensitive diagnostics, private data or the existence of a particular vehicle record.

Primary jobState whether GC’s public and private surfaces are operating normally and where a current interruption is being communicated.
Primary controlNo account data, no sign-in required, no technical diagnostics. The public can refresh or subscribe to incident updates.
Success exitReturn to the intended route once the aggregate component is operating; existing session/authority still applies.
Desktop wireframe

Specific about impact. Quiet about attack surface.

Every component is labelled by the outcome a person can recognise, not the vendor or internal subsystem. Amber is “degraded”; red is “interrupted”; green is “operating normally”.

01Use a single current-state headline and a timestamp with timezone.
02List product-facing components, not database names, regions or integration credentials.
03Incident update text describes impact, mitigation progress and next update time.
04Historical incidents are brief, resolved and do not contain private identifiers.

GC-930 / System · DenialPublic 403 rewrite / no redirect / no existence confirmation

Why can I not see this?

The answer must be truthful without becoming a reconnaissance tool. The page describes the viewer’s current access state and safe next step. It never names the hidden route, vehicle, document, person or object they attempted to reach.

Primary jobExplain that the current link cannot be opened by this viewer, without confirming whether the destination exists.
Primary controlSign in, return to Collection, or contact the appropriate human path—never “request access” to an unnamed protected item.
Rewrite ruleRemain on `/403` as a rewrite, not a redirect. Preserve no protected title, metadata or route label in visible UI.
Desktop wireframe

A firm no, without a leak.

This is intentionally less informative than a normal error page. It does not say “you need member access to X” and it does not show a breadcrumb, browser title or recovery link that confirms the protected destination.

01Heading speaks only about the present viewer and current link.
02Primary action is Sign in only when anonymous; otherwise use a safe Collection return.
03No route name, no prior page title, no document label, no suggested “similar” material.
04Support copy is generic and may route to Investor Relations without carrying the hidden path.
